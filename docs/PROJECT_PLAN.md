## 1. Purpose

Zero-shot named entity recognition (NER) models such as GLiNER receive entity types as free text. The
wording of each label (for example, "researcher" versus "scientist", or "organization" versus
"Organization") is therefore a hidden hyperparameter that practitioners rarely test. This project
delivers:

1. **A tool**: `labelsweep`, a pip-installable command-line tool that measures how much NER accuracy
   depends on label wording for a user's own labels and data, and selects wordings on a development
   split with an honest held-out check.
2. **A measured finding**: a pre-registered study across six public benchmarks and three GLiNER sizes.
3. **A write-up**: a blog post explaining the method, results and limits.

## 2. Evidence of need and novelty

| Claim | Source |
|---|---|
| Type descriptions alone change zero-shot NER F1 substantially | [ZeroNER, ACL Findings 2025](https://aclanthology.org/2025.findings-acl.805.pdf) |
| Reported zero-shot NER scores are inflated by label overlap with training data | [Familiarity, NAACL 2025](https://aclanthology.org/2025.naacl-long.37/) |
| GLiNER deployability studies vary models, not wording | [arXiv 2610.00007](https://arxiv.org/abs/2610.00007) |
| Closest tool covers zero-shot *classification*, not NER | [Tag Wording Analyzer](https://github.com/VatsalThakkar1326/zero_shot_classification_accuracy_matrix) |

Novelty sweep (2026-11-14): no dedicated NER label-wording tool found by GitHub repository-name search,
PyPI or Hugging Face. A zero result is not proof of absence; the claim is stated that way in the README.

## 4. Research questions

Pre-registered in [PREREGISTRATION.md](PREREGISTRATION.md) before the full grid was run.

| ID | Question | Hypothesis | Decision rule |
|---|---|---|---|
| H1 | How much does per-type F1 move with wording alone? | Median spread >= 5 F1 points in every run | Supported if true for all 18 runs |
| H2 | Does dev-selected wording hold up on test? | Test gain < dev gain; CI includes 0 on most datasets | Supported if both hold for >= 10 of 18 runs |
| H3 | Are larger models less sensitive? | Median spread: small > medium > large | Supported if strictly ordered on >= 4 of 6 datasets |
| H4 | Do meaning-preserving edits matter? | Casing or plural alone moves F1 by >= 2 points (median) | Supported if true in >= 15 of 18 runs |

Decision rules for H2-H4 were added on 2026-11-14 while 16 of 18 runs had completed; they are logged in
the pre-registration change log, and the write-up will report the raw numbers next to each verdict so
readers can apply their own threshold.

Outline:
1. Hook: one label, two wordings, very different F1 (real example from results).

## 9. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Hand-written alternative wordings reflect one author's choices | High | Medium | Pre-registered generator script; B3 adds independent paraphrases; stated in limits |
| Small types produce noisy spreads | High | Medium | Support filter (>= 30 test spans); counts shown per type |
| Coordinate sweep misses interactions | Medium | Low | Final label set evaluated jointly; stated in limits |
| Training-label overlap inflates scores (Familiarity) | Medium | Medium | Cited; relative comparisons only |
| Dataset licences | Low | High | Data is downloaded at run time, never redistributed; CrossNER is MIT; MIT Restaurant licence listed as "other" on Hugging Face and noted in README |
| Windows Application Control blocks exe shims | Observed | Low | `python -m labelsweep` documented |
| Overstating results in the blog | Medium | High | Every number traced to a committed result file; failed hypotheses reported |
